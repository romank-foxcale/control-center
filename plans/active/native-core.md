# native-core: The CC core runs natively on Windows, macOS and Linux with uv, without Nix or WSL

Lifecycle: active
Planning status: accepted

## Outcome

Milestone 1 of the kit redefinition. On a fresh clone of the kit template, on native Windows 11, macOS and Linux, with no Nix, no WSL and no system Python:

1. `cc` (POSIX shim) and `cc.cmd` (Windows shim) start the CC. When uv is missing, the shim downloads a pinned uv release into `.cc-local/tools/uv/<version>/`, checks its SHA-256 and uses it. uv runs a pinned Python and the locked dependencies (`uv.lock`, always `--locked`).
2. Every command of today's bash `cc` exists with the same name, arguments and exit codes, implemented in `scripts/cc.py`.
3. `cc check` runs every CC check natively (the Python test groups that `flake.nix` runs today), each in a temp `HOME`, and prints one row per check.
4. Rule hooks block on native Windows exactly as they do in WSL.
5. GitHub Actions runs `cc check` from a fresh clone on `windows-latest`, `macos-latest` and `ubuntu-latest`, plus a separate `ubuntu-latest` job that runs `nix flake check` for the optional Nix extra.

Nix stays as an optional Linux/macOS extra: `flake.nix`, `nix/`, `cc build|run`, `cc gc`, `cc relock` and Nix-defined project gates work only where Nix is installed, and fail with a clear message elsewhere.

## Non-goals

- No pixi adapters or native project gates. That is milestone 2 (a separate plan). The pixi feasibility spike (S3) only records evidence for it.
- No migration of existing CCs (di_CC and others). That is a separate plan; until it exists, `redefinition` is never merged into `main`.
- No deletion of `flake.nix`, `nix/lib`, `templates/project.nix` or `templates/workflow.nix`.
- No center-kit contract (`center.json`) work from decision 0032.
- No speed work beyond the hook latency limit (Dev Drive and similar are user-side).

## Evidence and current behavior

- `cc` is a 237-line bash script; every Nix call goes through `require_nix` (`cc:43-47`); `check` is `nix flake check --keep-going` (`cc:126`); feature overrides come from `scripts/worktrees.py nix-args` (`cc:56-64`).
- `cc.cmd` runs `./cc` inside WSL (`cc.cmd:9`).
- `flake.nix` checks are Python scripts in `pkgs.runCommand` with `HOME=$TMPDIR`: knowledge, agent-configs, council, rule-hooks, trello, events, repositories, prs, eval, settings-smoke (textual), bootstrap (only with `control-center.json`), plus Nix-only `contract-check` and `gate-venv`.
- `scripts/hook` is bash; `.claude/settings.json:25-67` calls it for five hook events; a hook failure or timeout (15 s) does not block (`scripts/hook:10-12`). The hooks block is generated by `scripts/agent-configs.py`.
- POSIX-only calls: `os.kill(pid, 0)` in `scripts/events.py:127` and `scripts/settings/state.py:29`; `pgrep` in `scripts/backup.py:106-132`; `wslpath` in `scripts/backup_where.py:101,119` and `scripts/disk.py:143-151,286`; `ps -u`/`os.getuid` in `scripts/store_gc.py:59`; `bash` in `scripts/eval/run.py:55` and `scripts/eval/scenarios.py:39`; `chmod` read-only in `scripts/repositories.py:49-62`.
- Python starts the extensionless `cc`: `scripts/council/run.py:287`, `scripts/settings/app.py:310,322,413`.
- Measured on the user's Windows 11 host (CC on C:): git status 185 ms native vs 7961 ms WSL `/mnt/c`; `rule_hooks_test.py` fails natively on an 8.3 temp path (`C:\Users\KOZYRE~1\...`).
- Risk audit: run `20261107-215427-risk` (in the scratch CC `~/cc-risk-trial`), verdict GO-WITH-CONDITIONS, 20 risks K1-K20. The assessors could not read this repository; they checked a kit copy at f3b4c0c.

## Invariants and decisions

- Same command surface: names, arguments, exit codes, `CC_FEATURE` feature context.
- Verify before push (kit decision 0028): a tree is stamped only when its gates ran and passed. A declared target gate that cannot run on this host is **FAIL**, never WARN or skip, and gives no stamp (K1).
- The stamp hashes the tree at the start of `verify` and refuses to stamp if the hash changed at the end (K16).
- The optional Nix extra row in `cc check`: on a host without Nix it shows `not run (optional, no Nix)` and does not fail the CC check; the CI Nix job is required on every PR instead.
- Internal callers never start the extensionless `cc`: they call `sys.executable <root>/scripts/cc.py` through one helper (K7).
- Platform code lives in one module, `scripts/hostos.py`: process liveness, executable resolution, process-tree stop, long-path canonicalization, native path conversion. No other script branches on `os.name`/`sys.platform` for these.
- Python is pinned with `.python-version` (3.14); the shims set `PYTHONUTF8=1`, and every `subprocess` text call sets `encoding="utf-8"` (K17).
- `cc.cmd` is the Windows entry point; no `cc.ps1` (K19). `cc` keeps the exec bit in git.
- A skip on Windows is allowed only for the Nix extra; CI fails when Windows runs fewer tests than Linux (K9).
- Docs say Nix is optional in the same PR that makes it optional (K12).

## Spike results (2026-11-07)

- **S1 GO** (Windows 11 host, Python 3.13; WSL Ubuntu, Python 3.14; macOS not run, covered by W6): `scripts/hostos.py` and its 10 tests pass. A mutation check catches the old `os.kill(pid, 0)` probe (2 of 4 liveness tests fail) and a plain `kill()` of a `.cmd` shim (the test hangs, K7). `claude` is `claude.exe`; `codex` and `cursor-agent` are `.cmd` shims; all three start and exit through `hostos.start`. Change to S1's outcome: `start()` + `stop_tree()` replace a single `run_streaming()`, so `providers.py` keeps its own read loop.
- **S2 GO with a condition**: details in `plans/active/native-core-s2.md`. Git for Windows is a prerequisite on Windows (`cc doctor` requires it). Every hook entry is `"command": "\"$CLAUDE_PROJECT_DIR/cc\" hook <name>"` with `"onFailure": "block"` (Claude Code >= 2.1.295); without Git Bash this form blocks every call (fail-closed). Never start the extensionless `cc` from PowerShell: that form allowed a forbidden call. The shims find `.cc-local/tools/uv/<version>/uv(.exe)` before `PATH`, `exec` uv, set `UV_PYTHON_PREFERENCE=only-managed` and a project-local `UV_PYTHON_INSTALL_DIR`, and install Python with `--no-bin`.
- **S3 GO** for milestone 2: details in `plans/active/native-core-s3.md`. pixi 0.84.1 locks Java 21 + PostgreSQL 18 + Maven + Gradle, .NET 8 and 10, and Python 3.12 + pytest on win-64, linux-64 and osx-arm64, and starts them on win-64 and linux-64 from one lock file. .NET 8 on Windows needs `MSBuildEnableWorkloadResolver=false`. No Docker backend is needed for these stacks.

## Integration and verification

1. On the user's Windows host, from a fresh clone of the integration branch with no uv on PATH: `cc doctor`, `cc check`, `cc verify`, `cc settings show`, `cc plan list`, `cc council status`. All pass or report Nix-extra rows as `not run`.
2. In a Claude Code session on that clone: an attribution commit, a write in `repos/reference/...` and an unverified push are each denied.
3. In WSL Ubuntu with Nix: `./cc check` (native rows plus the Nix extra row passing) and `nix flake check`.
4. CI: all four jobs green on the PR into `redefinition`.
5. A second risk council run on the finished branch, with the template readable by the assessors.

## Failure, rollback and stop conditions

- Every change lands on branches cut from `redefinition`; `main` and existing CCs are untouched. Rollback is dropping the branch.
- Stop and replan when S1 or S2 hits its stop condition.
- Stop when a check group can pass on Windows only with skips beyond the Nix extra.
- `redefinition` is not merged into `main` before the milestone 2 plan and the CC migration plan exist (K8, K11).

## Acceptance criteria

- Fresh clone, no uv, no Nix, no WSL, no system Python: `cc check` passes on Windows 11 (user's host and windows-latest), macos-latest and ubuntu-latest.
- Every bash `cc` command exists in `scripts/cc.py` with the same arguments and exit codes; `cc_test.py` asserts the list.
- Missing gate → FAIL and no stamp; changed tree during verify → no stamp.
- Rule hooks deny the three protected actions on native Windows with no system Python, under 5 s.
- Windows and Linux run the same number of tests, except the Nix extra.
- CI Nix job runs `nix flake check` green.
- Kit docs and skills no longer say Nix or WSL is required; decision 0033 is accepted and 0032 superseded.
